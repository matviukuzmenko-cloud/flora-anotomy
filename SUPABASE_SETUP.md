# Подключение Supabase

## Что уже подготовлено

- Регистрация и вход по нику и паролю через Supabase Auth.
- После входа ник отображается на главном экране; гостю доступно явное продолжение без аккаунта.
- Избранное, заметки, полив, сезонные наблюдения, история Flora и настройки хранятся в `public.user_data`.
- Для сохранённых растений сайт показывает внутрисайтовое напоминание о проверке полива, когда отмеченный интервал прошёл; это ориентир, не push-уведомление и не точный график полива.
- Изменения коллекции, отметок полива и сезонных наблюдений можно отменить кнопкой «Отменить» в уведомлении в течение нескольких секунд.
- Включены Row Level Security и политики, ограничивающие записи их владельцем.
- Без настроенного проекта сайт продолжает работать с локальным хранилищем браузера.

Для входа по нику без email используется сгенерированный внутренний адрес в домене `.invalid`. Это не настоящий почтовый адрес: включите вход без подтверждения email. У такого аккаунта не будет восстановления пароля по email. Пользователь сам придумывает пароль на сайте; пароли не записываются в таблицу сайта.

## Настройка проекта

1. Создайте проект в Supabase и дождитесь завершения запуска.
2. В **Authentication → Providers → Email** разрешите вход по паролю и отключите **Confirm email**. Это необходимо, потому что аккаунт идентифицируется ником и у него нет настоящего email для подтверждения.
3. В **SQL Editor** выполните весь файл [`supabase/schema.sql`](./supabase/schema.sql).
4. В **Project Settings → API** скопируйте Project URL и публичный `publishable` key (или legacy `anon` key) в [`supabase-config.js`](./supabase-config.js). Project URL должен выглядеть как `https://your-project.supabase.co` — без `/rest/v1/`. Не добавляйте `service_role` или `secret` key в сайт.
5. Для работы Flora API установите Worker-зависимости и войдите в Cloudflare, если ещё не входили:

   ```sh
   npm install
   npx wrangler login
   ```

   Разверните Worker:

   ```sh
   npx wrangler deploy
   ```

   `SITE_ORIGIN` уже задан в `wrangler.toml` для нового адреса Flora: `https://flora-anotomy.work.gd`. После смены адреса сайта Worker нужно развернуть заново, чтобы API разрешал запросы с нового домена.
6. В Supabase откройте **Authentication → URL Configuration** и задайте `https://flora-anotomy.work.gd/` как **Site URL**. Добавьте `https://flora-anotomy.work.gd/**` в **Redirect URLs**, если адрес ещё не указан.

## Публикация сайта на GitHub Pages

1. Загрузите файлы сайта в новый публичный репозиторий `matviukuzmenko-cloud/flora-anotomy` (ветка `main`, `index.html` должен находиться в корне). Затем откройте **Settings → Pages**, выберите публикацию из ветки `main` и папки `/(root)`, нажмите **Save**. Стандартный адрес будет `https://matviukuzmenko-cloud.github.io/flora-anotomy/`.
2. В **Settings → Pages** в поле **Custom domain** укажите `flora-anotomy.work.gd` и нажмите **Save**. Корневой файл `CNAME` в этом проекте уже содержит этот адрес.
3. `work.gd` обслуживается DNSExit как публичный суффикс, а DNS-поддоменом управляет аккаунт, которому он назначен. В панели DNSExit откройте настройки `flora-anotomy.work.gd` и задайте CNAME на `matviukuzmenko-cloud.github.io`. Не добавляйте `/flora-anotomy`, IP-адрес или `https://` в цель CNAME. Если панель автоматически создала A/AAAA-запись для этого имени, удалите её, чтобы не конфликтовала с CNAME.
4. Дождитесь обновления DNS — оно может занять до 24 часов. В **Settings → Pages** дождитесь включения HTTPS и отметьте **Enforce HTTPS**. Если DNSExit не позволяет управлять CNAME для выданного поддомена, настройку завершить нельзя без помощи их поддержки или другого поддомена с CNAME.
5. После публикации изменений разверните Worker командой `npx wrangler deploy` и обновите **Authentication → URL Configuration** в Supabase, как описано выше. GitHub Pages остаётся бесплатным хостингом; `work.gd` — DNS-поддомен.

Фотографии iNaturalist оптимизируются через публичный кэш-прокси wsrv.nl: запрос передаёт этому сервису URL открытой фотографии, а он отдаёт WebP подходящего размера и качества. Если прокси недоступен, сайт автоматически загружает оригинальный вариант iNaturalist напрямую. Другие источники изображений продолжают загружаться напрямую.

Имена пользователей приводятся к нижнему регистру для входа. Ник должен содержать 3–24 буквы, цифры, `_`, `-` или `.`; пароль — не короче 8 символов. Изменять политики RLS или делать таблицу доступной для `anon` не нужно.

После входа локальные данные объединяются с облачными. При совпадении заметок используется локальная запись, для дат полива — более поздняя дата, для сезонных наблюдений и избранного — объединение. Настройки и история чата также синхронизируются между устройствами.
